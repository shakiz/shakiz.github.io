# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

A static personal portfolio site served by GitHub Pages (`shakiz.github.io`). Pushing to `master` deploys, and GitHub Pages serves the committed files as-is. There is no package manager, linter or test suite.

- Build: `python3 build.py` (standard library only), or `python3 build.py --watch` to rebuild on every save while previewing. It regenerates the portfolio pages. Commit the generated HTML alongside its sources.
- Preview: `python3 -m http.server 8000` from the repo root, then open `http://localhost:8000`. Pages use root-absolute paths (`/css/site.css`), so opening files directly with `file://` won't load styles.

## Portfolio pages (generated)

The redesigned portfolio (Home, Work, project details, Guides, Writing, Resume, Contact) is generated by `build.py`:

- `build.py` holds the shared layout (head and meta tags, top nav, footer), the page list, and the site settings at the top: `LINKS` (profiles, booking, YouTube), `EMAIL`, `RESUME_PDF` and `FORM_ENDPOINT`. It renders each page body from `src/pages/*.html` and fills `{{ name }}` placeholders from that page's context. An unknown placeholder stops the build. It also writes `404.html` and `sitemap.xml`.
- Project detail pages (`/work/<slug>/`) all come from one template, `src/pages/project.html`, one page per entry in `projects.json`.
- `js/site.js` has three pieces: the mobile menu, filter chips and the contact form. Filter chips (`data-filter-for` / `data-filter-tags`) start hidden, so without JS every item shows; `data-filter-param` additionally syncs the chip with a URL query (the Guides page uses `?track=agentic|mobile`). The contact form posts to `FORM_ENDPOINT` (e.g. Formspree) when it's set; otherwise it opens the visitor's email app.
- Data comes from `content/projects.json`, `content/posts.json` and `content/guides.json`.
- Generated files start with a `Generated by build.py` comment. Edit the source and rebuild, never the output.
- Routes are folders with an `index.html` (`/work/` → `work/index.html`), so links end in `/`.
- `css/site.css` holds the design tokens (CSS variables on `:root`) and every portfolio component. Use the tokens instead of raw colours.
- Responsive breakpoints are mobile < 640px, tablet 640–1023px and desktop ≥ 1024px. All responsive rules live at the end of `site.css`. Where phones need shorter text, the markup carries both versions: `.dsk` (hidden on phones) and `.mob` (shown only on phones). `responsive_text()` in `build.py` emits that pair.
- Below 880px the top nav becomes a menu button and a full-screen overlay (`#site-menu`, built by `mobile_menu()` in `build.py` and driven by `js/site.js`). The header is sticky at every width. The swap only happens when `<html>` has the `js` class, so without JS the plain nav links stay visible.
- Unfinished content is written as visible `[bracketed]` placeholders, each with a `<!-- TODO: ... -->` comment beside it. `text()` in `build.py` adds that comment automatically for JSON strings. `grep -rn TODO src build.py`, plus `grep -rn '\[' content`, lists what's still open.

## Guides (hand-written, separate stack)

- **The Guides index** (`/guides/` → `guides/index.html`) is generated from `content/guides.json`, grouped into the tracks defined in `GUIDE_TRACKS` in `build.py`. It sits in the same `guides/` folder as the guide pages themselves.
- **Guides** in `guides/` are self-contained long-form pages that don't use `site.css` or the shared layout. Each has its own `css/<guide_name>.css` (the Claude guides share `css/agentic_dev.css`; some also pull Tailwind or Chart.js from a CDN), uses relative paths (`../css/...`), and starts with a `back-bar` linking to `/guides/?track=<track>`.
- Adding a guide means three things: the guide in `guides/`, its stylesheet in `css/`, and an entry in `content/guides.json` (then rebuild). The sitemap picks it up automatically.
- **Legacy hubs:** `agentic_dev.html` and `mobile_dev.html` are generated redirect stubs pointing to `/guides/?track=agentic` and `/guides/?track=mobile`.
- Interactive guides keep state in `localStorage` under versioned keys (e.g. `flutter-interview-guide.v2`, with a fallback read from `.v1`). If you change the stored shape, bump the version and keep the migration read.
